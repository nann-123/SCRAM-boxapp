## 一、v4 到底是什么修法（逐行核对，不是照抄提案描述）

### 根因：同一份 hand-out 被交付了多次

`euler_coupled` 分两个阶段：

1. **阶段一**（`:112-228`）：按**源 bin k** 遍历，算出每个源要交出的量，写进四个累加器
   `Q_1_esp / N_1_esp / Q_2evap_esp / Q_2cond_esp`。这四个数组**按目标 bin 编号索引**
   （写的是 `Q_2cond_esp(kloc(k), jesp)`）。
2. **阶段二**（原 `:378-400`，v4 改的这段）：把累加器交付给邻居。

原代码阶段二是**按源 bin k 迭代**的：

```fortran
DO k = 1, ns
   IF (grand(k) == 0) THEN
      IF (kloc(k) .NE. 1) THEN
         Q_esp(kloc(k)-1, jesp) = Q_esp(kloc(k)-1, jesp) + Q_2evap_esp(kloc(k), jesp)
```

累加器按目标索引、交付循环按源迭代 —— 于是**同一个累加器格被重复读了几次，取决于有多少个源共享同一个 `kloc` 值**。
本次相位 `kloc(k)` 全为 1，4 个源各交付一次，等于把同一份量送了多份。

插桩证据（v4 文件头"证据 2"）与之吻合：第一次守恒检查 `N_nouveau` 比 `N_ancien` 少 H，
第二次检查 `N_nouveau = 第一次 + 2H` ⇒ 净多 H 的一次额外交付。

**机制核对通过**：这是纯粹的"按错维度迭代"缺陷，与几何/边界无关。

### v4 的改法

把阶段二改成**按累加器索引（= 目标编号）迭代一次**：

```fortran
DO k = 1, ns
   IF (k .NE. 1) THEN
      Q_esp(k-1, jesp) = Q_esp(k-1, jesp) + Q_2evap_esp(k, jesp)   ! 蒸发交付给 k-1
      N_esp(k-1, jesp) = N_esp(k-1, jesp) + N_2evap_esp(k, jesp)
   ENDIF
   IF (k .NE. ns) THEN
      Q_esp(k+1, jesp) = Q_esp(k+1, jesp) + Q_2cond_esp(k, jesp)   ! 凝并交付给 k+1
      N_esp(k+1, jesp) = N_esp(k+1, jesp) + N_2cond_esp(k, jesp)
   ENDIF
ENDDO
```

**这个改法是自洽的**：累加器 `Q_2evap_esp(k,jesp)` 的定义就是"bin k 要交给 bin k-1 的量"
（阶段一里 `grand(k)==0` 时写入，且 `kloc(k)-1 = k-1`），所以"目标索引 k"的蒸发量恰好落到
`k-1`，一一对应、只交付一次。

### v4 的第二个改动：除零保护（7b）

把 `IF(…RQ(k)/Q(k)… .AND. Q(k) .NE. 0D0)` 改成先判 `IF (Q(k) .NE. 0D0)` 再算比值。
原因在源码里能直接看到：**Fortran 不短路求值**，`Q(k) .NE. 0D0` 写在第三个 `.AND.` 操作数里，
求值发生得太晚。这个改动是对的。

### v4 的第三个改动：给信息性打印加前缀（7d）

改了三处打印文案（`:248/:258` 的"ds algo"、`:371` 的"交付前中间量"）。核对结果：

- 改后文案**不再包含** `"non conservation"` 这个子串 ✅
- 但 `probe_cell.py:39` 的致命判据里还有裸 `"STOP"`；改后文案含 `"sans STOP"`，
  已有 `LOG_INFO_STOP_LITERAL` 正则剔除 ✅
- **`run_service.py:558-563` 的 `_FATAL_LOG_PATTERNS` 仍是裸 `"STOP"` / `"negatif"` / `"non conservation"`，
  没有 `sans STOP` 的豁免** ❌

⇒ **只在 `scripts/linux/probe_cell.py` 修过判据，GUI/服务路径没修**。这是"修了也判 failed"的直接原因。

1. **先修判据，再谈修数值**：`run_service.py` 与 `probe_cell.py` 用同一套致命判据
   （只认 `non conservation du nombre total` / `non conservation de la masse totale` / 真 `STOP` /

   **这一步纯 Python，本机可做、可回归。**
2. **把 v4 落回仓库源码**（`git apply --ignore-whitespace`，本仓库 CRLF/LF 混杂，必须带这个参数）。
3. **装工具链后建两棵树验证**：`stock`（未修）与 `patched`（v4）各跑
   `gmd_hazy_coag_cond + method=6` 一个完整 12 h，判据 = 跑满步数 + 活 STOP 计数 0 +
   数量/质量守恒到 `EPS_machine`。同时用 `-ffpe-trap=zero,invalid,overflow` 构建定位 7c 的其余浮点路径
   （提案说 `aec_drv` 那处未修）。
4. **在拿到第 3 步结果前，界面保留 6 但标注为"实验性、论文未验证"**，教学模板默认仍是 2（现状）。
   不建议现在撤掉——撤掉会丢掉"作者确认过的真实缺陷"的第一个修复验证对象。

## 五、关于"定时自我调试还要不要做"

### 判断

**当前形态的定时自动调试已经到边际收益极低的阶段**，理由来自仓库自己的记录：

- `docs/linux_debugging/hunt_plan.md` 自己诊断过："矩阵跑满后池子内容不再变化 → 反复跑同类格子"、
  "只记 clean/bug，'跑一遍没崩'不携带信息"。
- 2026-09-13 收口提交（`ca24dc4`）明确写着"**停止 Linux 侧自动调试**"，
  并更正了 Q-27 误报 —— 即**上一轮的自动结论本身有假阳性**，且根因是判据（关键字）失真，不是缺发现能力。
- 本次核查又发现一条同类的：`run_service.py` 的裸 `"STOP"` 判据至今未修，
  意味着**任何未来跑 euler_coupled 的自动轮次都会产出假 failed**。判据不修，再加频率只是放大噪声。

### 建议的分工

| 该自动化 | 不该自动化 |
|---|---|
| **判据/量纲/一致性检查**（图 vs CSV、开关反证、守恒残差、量级守卫）——确定性、可回归、不产生假阳性 | **开放式"找新 bug"扫格子**——已经收敛，且需要领域判断才能定性 |
| **回归看门**（每次改动后跑既有判据集，输出三态：ok / 已知项 / 新问题） | **定时"自我调试"**——除非有新假设；没有新假设的重跑 = 重复 |
| **新缺陷形态的探针**（本轮的"绘图正确性"就是一类全新的、可判定的检查面） | — |

### 一句话

**把"定时"换成"按假设触发 + 判据先修"。** 具体三件事：
① 修 `run_service.py` 的判据（今天就能做）；
② 把第五节列出的 5 条绘图判据加进 `run_standard_tests.py`（明天能做，且能自动抓住本次两类问题）；
③ 之后只在"有新假设"时开轮次，不再定时。
