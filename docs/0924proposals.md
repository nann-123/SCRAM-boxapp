## 0. 给老师的三句话

1. **两条硬约束决定了本次提案的形状**：① Windows 发行核 `ProgramSCRAM.exe` **仍是 1.1 构建**（1.2 独有字符串 0 命中），本机无 Fortran 工具链；② 因此**任何 `.f90` 改动今天在 Windows 上都不会生效**（改了也不生效 = 静默不一致。上一轮就因此把一个已经修好的问题卡了一个多月，用户侧一点变化都看不到）。
2. **据此，本次把 10 项可做的改动全部放在 py 侧**（不需要工具链、零回归风险、立即生效），把 **5 项必须动内核的改动单独列成"F 类"**，只出补丁 + 给作者的信，等 Windows 能重编译后再落地。
3. **有一个残余风险必须说清**：论文验证模式（配置里把"成核模型"设为 5，下文简称 nl=5）的外混臂，在 py 侧**只能"拦住不让用户跑"**，**不能让它变得可用**。它在当前内核下有两种错法（见 P-01）：一种直接报错停机，另一种能跑完但**初值偏高 6 倍**。要让它真正可用，必须走 F 类（改内核 + 重编译 + 作者确认该模式是否支持多列）。

### 术语对照（读后面各节前先看这张表）

本文用到的都是软件里的字段名/内核术语，这里给出大白话解释：

| 文中写法 | 大白话 |
|---|---|
| **nl=5**（= `nucl_model=5`） | 配置里把"成核模型"设为 5，即**论文里的雾霾验证专用模式**：初值改用内置的霾天分布、硫酸盐源也内置硬编码 |
| **内混 / 外混**（internal / external mixing） | 同一颗粒里同时含多种组分（内混）vs 不同颗粒各含一种（外混） |
| `tag_external` | 初始态按哪种给：**0 = 内混**（所有组分在同一列），**1 = 外混**（按组成分列摆放） |
| `n_frac` | 组成轴切几段：**=1 就是单列（内混）**，**>1 是多列（外混网格）** |
| `tag_init` | 初值来源开关：**0 = 用内置的霾天/城市/清洁三套分布自动算**，**1 = 用配置文件里逐档写好的质量**（出厂都是 1） |
| `tagrho` / `fixed_density` | 密度模式：用固定密度还是按组分算真实密度；后者影响内置分布的幅值 |
| `dtmin` | 界面上的"最小时间步（秒）" |
| `redistribution_method` | 粒径重分布方法（把粒子从一档搬到另一档的算法） |
| 凝并 / 冷凝 / 成核 | 三个物理过程（coagulation / condensation / nucleation），界面上各有开关 |
| `Mass Cond` / `Nub Coag` | 内核自己打印的两个计数："冷凝产生了多少质量"、"凝并发生了多少"。**判断某个过程到底有没有算，看它们最可靠** |
| "孤儿格子"（orphan） | 内核的报错用词，指**有质量、但粒子数是 0** 的格子（质量无处附身），与它对称的是"有粒子数、没质量" |
| 粒径档 / 组成档（列） | 第一条轴：按粒径分段；第二条轴：按化学组成分段。"一列"= 一种组成状态 |

## 1. 决策原则：为什么"先改包装层"

### 1.1 分层判据（沿用项目既有五分类）

| 类别 | 含义 | 本次提案里对应的现象 |
|---|---|---|
| `port`（包装层写错） | 内核本身是好的，是界面没把值送对、或没送过去 | "环境状态"选了没用；载入配置后混合假设恒为外混；"最小时间步"改了没用；内外混对比里混入了初始态差异 |
| `port-defect`（内核约定没复刻） | 内核有明确的输入约定，包装层没照着做 | nl=5 的配置文件行数契约（已修好）；本次的 nl=5 布局 / 初值护栏 |
| `upstream-defect`（内核自身逻辑错） | 2015 年那份代码本身的错 | nl=5 多列初值读了未初始化数组；nl=5 初值被重复投放；"重分配方法 6"数量不守恒 |
| `undefined-domain`（模型没定义过的输入） | 这种输入在模型语义里从没规定过怎么算 | "初始质量为 0、但粒子数不为 0"；nl=5 的多列初值 |
| `by-design`（作者有意的决定） | 为特定场景写死的经验值 | "重分配方法 3/5"粒子数暴涨；排放只在前 44 分钟发生 |

**规则**：前两类与第四类一律在 py 侧解决；第三类与第五类不动内核，只做"拦截 + 记录 + 给作者"。

### 1.2 为什么先改包装层（成本对照）

| 维度 | 改包装层（Python） | 改内核（Fortran） |
|---|---|---|
| 能否在本机立即生效 | ✅ 立即 | ❌ **必须先重编译**，本机无工具链 ⇒ 阻塞 |
| 会不会改既有数值基线 | ❌ 不会（除非有意） | ⚠️ 会，需全量重采（1.2 基线重采本身还是待办） |
| 需要作者审阅 | 不需要 | **需要** |
| 回归验证成本 | 跑 `install_logs/verify_0924.py` + 标准测试 | 需 Linux 重建 + Windows 重建 + 保真度 gate 复测 |
| 可回滚性 | 改包装层：回退一行代码 | 改内核：需回退二进制 |

⇒ **结论**：只在包装层无法表达该语义时才动内核。本次判定必须动内核的只有 5 项（见 §4）。

## 3. P 类：包装层提案（10 项，全部可立即做）

### P-01　论文验证模式（nl=5）的外混臂拦截

**现象**：nl=5 时若配置为"用单列组成（`tag_external=0`）却要求摊到多列外混网格（`n_frac>1`）"，当前内核（1.2）会在重分布前体检时**直接报错停机**：
`ERROR STOP orphan mass/number before remap` —— 意思是某个格子"有质量、粒子数却是 0"，新内核拒绝把这种不配套的格子搬下去。
若把 `tag_external` 改成 1，程序能跑完，但**初始总质量是内混臂的 6.0000 倍**（`n_frac=5` 时 18 倍，终态粒子数比正好 6.0000）—— 这不是物理差异，是**同一份初值被重复投放**。
**出厂路径**：两个雾霾验证模板（`gmd_hazy_condensation` / `gmd_hazy_coag_cond`）都用 nl=5；用户在界面上点"比较内混/外混"时，外混臂会把 `n_frac` 设成 3 ⇒ **必然踩到上面第一条（停机）**。

| 位置 | 改法 |
|---|---|
| `app/services/run_service.py:339` `_with_mixing_assumption` | 入口处判 `int(data["scalars"].get("nucl_model",0)) == 5` 且 `scheme == "EXTERNAL_MIXING"` ⇒ 抛一个**带解释的** `ValueError`（而不是让核心崩） |
| `app/services/run_service.py:194` `run_comparison` / `:203` `run_batch_comparison` | 同一判据下**只跑内混臂**并在返回行里带 `"skipped": "EXTERNAL_MIXING"` + 原因 |
| `app/config_binding/config_model.py:327` `validate()` | 加同一条闸门（与已有的"求解器号越界"前置闸门同一位置、同一风格），让"运行前校验"也能拦到 |
| `app/views/main_window.py:1097` `_start_runs` | 比较按钮在 nl=5 时**置灰 + 悬停提示说明**（比弹窗更友好） |

**为什么不做"让外混臂也能跑"**：那是 F-01/F-04 的范围（要作者确认 nl=5 是否支持多列 + 需重编译）。

**验收判据**：
- nl=5 + 比较 ⇒ **不产生外混臂运行目录**，日志与状态栏给出可读原因；
- 非 nl=5 的模板（`gmd_paris_*`、`tutorial_minimal`）比较行为**逐位不变**；
- 断言：nl=5 时递给核心的任何配置文件都不满足 `(tag_external==0 and n_frac>1)`。

**风险 / 连带**：① 雾霾模板的"比较"能力被移除 ⇒ **教学手册与本科实验手册里"点比较"的描述要同步改**（与 P-04/P-05 的界面改动**合并做一次**）；② 若老师希望保留"能跑但明确告警"，改为**软告警 + 结果目录写 `WARNING_nl5_external.txt`**（见下方备选）。

**备选强度**：
- **A（推荐）硬拦截**：nl=5 不允许外混臂（杜绝拿到错数）；
- **B 软告警**：允许跑，运行前弹窗 + 结果目录写警告文件（保留"能复现这个坑"的能力）；
- **C 只禁比较、允许单跑外混**：保守，但用户单独跑外混臂时仍会触发停机。

### P-02　nl=5 前置护栏（布局 + 初值口径）

**现象**：nl=5 的初值与硫酸盐排放**钉死在编译期的两个固定位置**（第 2 个物种 = 黑碳、第 4 个物种 = 硫酸盐，写在内核的 `INC/pointer.inc` 里），所以它**只在 30 个物种的那套配置下成立**。换成 2 物种配置实测：程序**不报错**、正常结束，但初始总质量只剩一半、凝并/冷凝计数全为 0（静默失效，比崩溃更难发现）。另：nl=5 的初值幅值会随物种表变化（同一个雾霾场景，2 物种布局算出 57.537、30 物种布局算出 37.679）。

| 位置 | 改法 |
|---|---|
| `config_model.validate()` | nl=5 时校验：第 2 个物种名含 `BC` 且第 4 个含 `SO4`（对应上面那两个固定位置）；不满足 ⇒ 报错并说明"该模式只用内置的霾天分布且位置钉死，请改用 30 物种的 baseline 配置" |
| `run_service.prepare_run` | 同判据；若老师希望更宽松，退化为"物种数不等于 30 时**告警**而非拦截" |
| 结果报告（`app/services/report_service.py`） | 无论拦截与否，**回显本次初值来源**："配置文件里逐档写的质量" / "内置的霾天·城市·清洁分布（nl=5）" |

**验收判据**：2 物种布局 + nl=5 ⇒ 运行前就被拦下（或至少报告里显式告警）；30 物种布局 + nl=5 ⇒ 行为与现状逐位一致。

**风险**：判据依赖物种**名字**（`BC` / `SO4`），若用户改名会误判 ⇒ 建议同时提供一个"按第 2 / 第 4 个物种"的兜底判据，两者取或。

### P-03　从配置文件反推混合假设

**现象**：读入配置文件时，程序把"混合假设"**写死**成外混（`config_model.py:101` 的返回字典），界面下拉又是锁死的 ⇒ 载入任何配置文件（包括本该是内混的 `n_frac=1` 配置）都只能按外混跑。（这段解释文字的界面键名问题已在 09-23 修好。）

| 位置 | 改法 |
|---|---|
| `config_model.parse()`（`:101` 的 `"mixing_assumption": "EXTERNAL_MIXING"` 硬编码处） | 返回前按 `n_frac == 1 ⇒ INTERNAL_MIXING`、`n_frac > 1 ⇒ EXTERNAL_MIXING` 反推（**判据极简**，与 `_with_mixing_assumption` 的写入口径正好互逆） |
| `config_model.validate()`（`:327`） | 加一致性校验：`n_frac==1` 却标 `EXTERNAL`（或反之）⇒ 报错 |
| `main_window.py:214-218`（下拉创建 + 锁定）／`:989-995`（弹回逻辑） | 保持"锁死"不变（错误切换会导致 fraction 表结构不匹配，原设计意图是对的） |

**验收判据**：载入 `n_frac=1` 的配置文件 ⇒ 下拉显示内混；载入 `n_frac=3` 的 ⇒ 显示外混；对 `gmd_paris_full` 的既有结果**逐位无变化**。

**收益**：顺带减少 P-06 所说的"两臂差异里混入初始态"的诱因。

### P-04　环境状态与"初值来源开关"联动

**现象**：三个场景（霾天/城市/清洁）**功能是好的**，但被三层门槛挡住：① `tag_init=0`；② `nucl_model=5` 时硬编码分支优先；③ 改组分比例那段还要求 `tagrho=1`。出厂 `tag_init=1` ⇒ 选哪个都一样（逐位相同）。实测把 `tag_init` 设为 0 后，三场景**确实产生不同结果**（终态质量 EXT `11.1139/11.1076/11.1028`，来自冷凝 `Mass Cond≈11.09`）。

| 位置 | 改法 |
|---|---|
| `_collect_data()`（`main_window.py:705` 一带） | **推荐 A′**：不是 nl=5 时，选场景 ⇒ 自动把 `tag_init` 写成 0；是 nl=5 时**禁用场景下拉**并提示"nl=5 使用内置霾天分布，本项无效果"（避免与 P-01/P-02 打架） |
| 界面文字（中英各 1 条） | 改写「环境状态」的悬停说明：明确"本项仅在【初值来源开关 = 用内置分布】且不是 nl=5 时影响初值；选场景会改用内置的三模态对数正态分布，配置文件里逐档写的质量将被忽略" |
| 报告（`report_service`） | **无论如何都做**：回显"本次初值来源"，与 P-02 复用同一段文字 |

**⚠️ 这是本批**唯一会改变出厂行为**的一项**（现在选场景无效果，改后会有数值影响）⇒ **必须老师点头**。

**备选**：**A** 无条件联动（更直接）／**A′ 条件联动（推荐）**／**B** 把 `tag_init` 暴露到界面（更透明但多一个概念）／**C** 移除下拉（零风险零收益）。

**验收判据**：`nucl_model≠5` + 场景三选一 ⇒ 运行日志/报告里的初值来源不同、终态质量不同；`nucl_model=5` ⇒ 下拉禁用且提示可读；`gmd_paris_*` 在**未选场景改动**时行为不变。

### P-05　"最小时间步"控件的处置

**现象**：内核里 `dtmin` 只有 3 处出现 —— 一处注释、一处读取、一处声明，**0 处使用** ⇒ 改任何值结果逐位相同；而且注释承诺的"把新步长限制在最小/最大步长之间"**从未实现**（注释引用的 `time.inc` 在作者原始代码里也不存在）。**补充核实（本次新查）**：最大步长 `DTMAX = 10.D0` 其实是存在的（`INC/paraero.inc:83`、`ModuleInitialization.f90:85`），缺的只是 `adaptime` 里那句钳制。

| 位置 | 改法 |
|---|---|
| `main_window.py:263、273` | **方案 A（推荐）**：移除控件 + 移除那一行 Form |

### P-06　内外混对比的差异显式化

### P-07　绘图异常峰值标注

**现象**：`gmd_paris_full` 出图时，粒子数曲线有一条高位异常：末态/初态 = **132 倍**，峰值≈初值 **735 倍**、≈终值 **1000 倍**；峰值时刻（2443–2484 s）紧贴排放窗口上沿 2643.76 s，**指向排放项**。内核自己认得出来（`anomaly_flags.csv` 里有"数量跳变"/"单个粒径档占绝对多数"两个标记），绘图层也加了标注，**但图仍照常画出 1e13 的峰值**，学生/读者会当成物理结果。

### P-08　初始质量为 0 时的输入护栏

**现象**：当配置选择"用逐档写好的质量"（`tag_init=1`）而**逐档质量全为 0、粒子数却不为 0** 时，会出现三件怪事：凝并整个被跳过（凝并计数 = 0）、冷凝同样不产生任何质量、内外混的终态粒子数相差 **4 个数量级**（4.1e9 对 0）。这是**模型没有定义过的输入**（"有数量、没质量"在物理上自相矛盾）。

| 位置 | 改法 |
|---|---|
| `config_model.validate()` | 加一条**可关的**护栏：`tag_init==1` 时若某档"质量总和 = 0 而 `init_bin_number > 0`" ⇒ 报错（默认开启）；错误文案给出两种修法（补质量 / 把该档粒子数置 0） |
| 界面文字（中英各 1 条） | 新增一条解释 |

**为什么现在做**：出厂模板在 2026-07-27 已换成非零初值，所以**在应用里点几下碰不到**，但**手工载入配置文件就能复现**（触发路径从未消失）。等作者定性期间，先在界面层挡住是零成本的。

**备选**：**A 界面禁止（推荐）**／B 只告警／C 等作者回函（届时可能不需要）。

**验收判据**：载入 `zero_initial_mass_test.cfg` ⇒ 运行前被拦下并给出可读原因；出厂 8 个模板全部仍可运行。

### P-10　"生效性体检"流水线（防"改了不生效"）

**背景**：`.f90` 是图纸、`exe` 是成品，是两个独立文件。仓库那份 Windows 内核是 2026-05-15 构建的，此后的内核改动**都没进它**（上一轮因此把一个已修好的问题卡了一个多月，用户侧完全看不到变化）。现状靠人记得住"重编译 → 覆盖成品 → 删用户目录暂存副本 → 跑标准测试"。

| 位置 | 改法 |
|---|---|
| 新增 `scripts/apply_runtime_fix.py` | 把上述四步串成一条命令，并**强制**在最后跑 `check_runtime_version.py` + `run_standard_tests.py`；若版本自检仍是 1.1 而本次改了 `.f90` ⇒ **显式失败**并提示"成品未更新" |
| `docs/windows_devkit_readme_zh.md` | 补一节"改核后的唯一正确流程" |

**说明**：这不是修缺陷，是把上一轮的教训**机制化**。本机没有工具链时它跑不了第 1 步，但可以以"仅检查成品版本"模式运行（退化为当前 `check_runtime_version.py` 的能力）。

**验收判据**：在未重编译的情况下改动任意 `.f90` ⇒ 脚本以非 0 退出并打印"图纸与成品不一致"。

| 编号 | 对应的现象 | 改法 | 为什么 py 侧做不到 |

| **F-01** | 论文验证模式外混直接停机 | `ModuleDiscretization.f90:669-679` 这一整段**对 nl=5 跳过**（该段的语义是"把内混初值摊到外混网格"，而 nl=5 的初值已由前面按列摆好） | py 侧只能"拦住不让跑"，**不能消除那个"有质量没粒子数"的格子**；要让 nl=5 外混可用只能改内核 |

## 5. 给作者的信（问题清单，可直接转发）

> 摘自内部审查报告 `docs/nl5与bug28审查_20260921.md` §7（文件名里的编号可忽略），只保留需要作者定性的部分。

5. **两处耦合提醒**：(a) nl=5 初值幅值经 `fixed_density` 依赖物种表（换布局同一场景初值总量会变）；(b) 初值与排放钉死固定槽位 `EBC=2 / ESO4=4`（所以 nl=5 只在 30 物种布局下成立，2 物种布局下硫酸盐被静默忽略、`Mass Cond=0`）。

7. **排放窗口**：`2.64376e3`（44 min）这个数的来历？为何 `nucl_model=5` 用 43200 s？`:1274`/`:1287` 两个步长守卫不随 `nucl_model` 变，是有意的吗？
